# ADR-0030：CI-144 v2.0 Seq-Counter 32-bit 扩展方案

## 状态
**Draft**（2026-08-29，Beta 阶段评估，不阻塞当前 v2.0-alpha.0 设计冻结）

## 上下文
CI-144 v2.0 当前设计 Seq-Counter 为 16-bit（65536 帧空间），回绕时触发密钥轮换（规则 7）。在高并发多租户场景下（如 10000fps），16-bit 约 6.5 秒回绕，密钥轮换频繁。32-bit（42.9 亿帧）可大幅减少轮换频率，但需要扩展 BIND-19 帧结构。

## 决策（初步定案，Beta 阶段评估）
- 当前 v2.0-alpha.0 保持 16-bit 设计 + 密钥轮换机制（规则 7），不阻塞设计冻结
- 32-bit 扩展方案在 Beta 阶段评估，包含：
  1. 帧结构扩展方案：是否扩展 BIND-19 头部从 8 字节到 10/12 字节？还是将 Seq-Counter 放在 PAL 的 Reserved 区域？
  2. 向后兼容评估：v1.0 接收端如何处理扩展后的帧？v2.0 16-bit 与 32-bit 如何共存？
  3. 密钥轮换机制是否保留？32-bit 回绕风险极低（10000fps 下 4.9 天），但是否仍需定期密钥轮换（安全考虑）？
  4. 迁移路径：从 16-bit 升级到 32-bit 的平滑迁移方案
- 若 Beta 评估通过，以 ADR 形式升级规范，在 v2.0-beta.1 或 v2.0-rc.1 中落地

## 后果
- v2.0-alpha.0 实现方按 16-bit 实现，不受 32-bit 扩展影响
- 32-bit 扩展若通过，需要实现方升级（但接口可保持兼容）
- 密钥轮换机制在 32-bit 下可能简化（但定期轮换的安全需求仍需评估）
