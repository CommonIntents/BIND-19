# ADR-0026：CI-144 v2.0 密钥轮换期间帧处理 + ACK 超时机制

## 状态
**Draft**（2026-08-29，Alpha 实现期间待锁定）

## 上下文
发送 KEY_ROTATION 帧后、接收端确认前，数据帧的处理方式（旧密钥 or 新密钥）和 ACK 超时机制需明确定义。

## 决策（初步定案，Alpha 编码前最终确认）
- **轮换期间帧处理**：发送轮换帧后，等待 1 个 ACK 确认再切换；期间数据帧仍用旧密钥，避免丢包
- **ACK 超时机制（fail-closed，修正项-01）**：超时 100ms 重试，最多 3 次。若 3 次全部失败，发送端必须：
  1. 触发硬告警（ERROR 电平 + 声光指示）；
  2. 停止发送所有数据帧，进入"密钥轮换失败"安全状态；
  3. 等待人工物理复位或带外管理干预后方可恢复。
- **严禁回退至旧密钥并继续发送数据帧**（状态不一致比停止服务更危险）
- 理由：等待 ACK 避免丢包，旧密钥保证连续性；fail-closed 是安全设计的正确应用，状态不一致比停止服务更危险

## 后果
- 需实现 ACK 帧格式和超时重试机制
- 需定义回退流程（3 次失败后如何处理）
- 需定义告警机制（轮换失败时通知谁）
